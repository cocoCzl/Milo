## 背景视图与撤销的技术边界

`tests/probes/viewLifecycle.test.ts` 使用真实 Milkdown 和 ProseMirror history：编辑后保存精确 EditorState，销毁旧 EditorView，用同一 State 重建，undo／redo 正确且 `editorStateCtx` 跟随新状态。随后把 `editorViewCtx` 设置为新视图，调用 Milkdown `editor.destroy()`，新视图仍未销毁——内部 view 插件闭包持有原实例，需要单独销毁新视图。

因此 State 保留可行，但只替换公开 ctx 并不足以安全交接所有权。生产还需协调 NodeView、DOM 事件、插件视图、选择、滚动、组合输入、异步图片、flush 注册和当前 `editorRef`。当前没有用 destroy/reparse、清空 history 或重新读磁盘实现伪缓存。下一步是给 Milkdown view 插件提供显式 attach/detach 所有权，再在真实文档插件组合上测试；探针不是已启用的缓存实现。

Source 精确文本比较避免无改动切换重置历史；实际改动后返回仍建立新的可视历史。前版本只读检查点每标签最多一个、仅会话内，不承诺持久恢复。异步安全检查结果必须再次匹配文档身份／路径／revision／模式／活动／外部变化／composition。尝试用 `execCommand('insertText')` 实现 Source 全部替换时，实际 WebKit 撤销跳过预期版本，因此撤回该实验；未将其包装为已完成替换功能。Source 支持整文件精确、区分大小写的前后查找，替换暂缺。
