# 已知问题

Milo 当前是 macOS 0.3.0 预发布版本。普通 Markdown 文件仍是权威来源；测试版使用前请准备可丢弃或已备份的文档。

## 当前限制

- 20 标签全部访问的正常 Release footprint 仍超过 200 MB 预算。2026-11-16 的短合成样本为 259.15 MB，逐篇编辑保存后 266.47 MB；同进程三轮关闭后的采样为 183.91、198.81、188.21 MB，没有确认线性泄漏。原生探针确认 20 个 EditorView 全部关闭后 20 个实际销毁、文件监测订阅归零；这不等于所有底层对象已 GC。历史 225.92 MB 和宽窗口仅访问首篇约 200.87–208.65 MB 属于不同场景，不可直接作优化对比。有界缓存仍未实现，未通过丢弃撤销历史降低占用。
- 候选输入期间 Cmd+S/Cmd+Q 的 `s/q` 混入仍未解决。macOS 自带拼音的自动化逐键测试在段落、标题、代码块、表格和 Source 均影响候选；composition 更新可先于带 meta 的命令 keydown，保存确实等待组合结束。Q 的 DOM 修饰键事件到达不等于原生退出请求到达；最小 WKWebView 对照未成功使用同一输入源，不能归因为上游。尚未排除自动化投递、macOS 输入法、WKWebView 或共享应用处理，保留现有输入逻辑，未声称修复。
- 某些 Dock、应用切换、最小化恢复和窗口过渡仍缺少可靠的原生测量；浏览器模拟测试不代表这些行为已通过。
- WYSIWYG 编辑可能规范化列表、围栏、表格和硬换行等 Markdown 格式，未承诺整篇字节级无损。
- 源码模式与 WYSIWYG 使用不同编辑模型，跨模式统一撤销尚未实现；源码实际修改后返回 WYSIWYG 会建立新的可视编辑历史边界。
- WebKit 在少数软换行边界可能绘制出位置不理想的光标；文档内容、选择和 dirty 状态不受影响。
- 当前只在 Apple Silicon 主机上完成原生验收；Intel 和其他 macOS 版本仍需单独验证。

## 测试边界

启动阶段、解析和模型输入响应已有诊断样本，但它们不等于点击应用到首次可输入或像素响应。原生 IME、磁盘保存、窗口生命周期和 footprint 结论应以 [编辑器状态摘要](EDITOR_STATUS.md) 与发布运行手册为准。浏览器测试使用模拟 IPC，不能替代 Tauri/WKWebView 验收。

本轮逐进程表、资源/历史生命周期、输入法复现矩阵、已排除项及仍未验收的关闭/退出/最小化边界见 [内存与拼音专项诊断](MEMORY_IME_DIAGNOSTICS.md)。没有安全有效的驱逐对照收益，也没有确认输入法根因，因此只提交诊断设施和文档。

已完成的保存、恢复、外部冲突、输入状态恢复和共享目录监测器修复不再在此重复列出逐轮过程；变更原因和代码历史保留在 Git 提交中。
