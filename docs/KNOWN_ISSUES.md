# 已知问题

Milo 当前是 macOS 0.3.0 预发布版本。普通 Markdown 文件仍是权威来源；测试版使用前请准备可丢弃或已备份的文档。

## 当前限制

- 20 标签全部访问的正常 Release physical footprint 超过 200 MB 预算；短合成样本为 259.15 MB，编辑保存后 266.47 MB。**尚未确认真实泄漏，也未排除长期泄漏。** 原生诊断确认 20 个 EditorView 全部关闭后实际销毁 20 个、存活 0 个，文件监测目录和订阅归零；这不等于底层对象已 GC 或进程内存已全部归还系统。有界驱逐和后台视图缓存尚未实现。
- 候选输入期间 Cmd+S/Cmd+Q 的 `s/q` 混入仍未解决，段落、标题、代码块、表格和 Source 的原生拼音自动化逐键样本均观察到候选受影响。**当前证据不足以归因到 Milo、WKWebView、macOS 输入法或自动化输入。** 组合文本更新可先于命令 keydown；Cmd+Q 的 DOM 修饰键事件到达不代表原生退出请求到达。最小对照未使用相同输入源，不能据此归因；保留现有输入逻辑，未通过屏蔽 `s/q` 绕过问题。
- 某些 Dock、应用切换、最小化恢复和窗口过渡仍缺少可靠的原生测量；浏览器模拟测试不代表这些行为已通过。
- WYSIWYG 编辑可能规范化列表、围栏、表格和硬换行等 Markdown 格式，未承诺整篇字节级无损。
- 源码模式与 WYSIWYG 使用不同编辑模型，跨模式统一撤销尚未实现；源码实际修改后返回 WYSIWYG 会建立新的可视编辑历史边界。
- WebKit 在少数软换行边界可能绘制出位置不理想的光标；文档内容、选择和 dirty 状态不受影响。
- 当前只在 Apple Silicon 主机上完成原生验收；Intel 和其他 macOS 版本仍需单独验证。

## 测试边界

启动阶段、解析和模型输入响应已有诊断样本，但它们不等于点击应用到首次可输入或像素响应。当前实现、性能样本和原生验收边界汇总于[编辑器状态摘要](EDITOR_STATUS.md)，发布要求见[发布运行手册](RELEASE.md)。浏览器测试使用模拟 IPC，不能替代 Tauri/WKWebView 验收；内部逐轮诊断记录和临时产物不纳入公共文档。

已完成的保存、恢复、外部冲突、输入状态恢复和共享目录监测器修复不再在此重复列出逐轮过程；变更原因和代码历史保留在 Git 提交中。
